## 二、打包

Windows 上把文件放同一个文件夹，双击 `build_exe.bat` → `dist\BillingTool.exe`。

## 三、燃油费率记忆（本次新增）

- 界面第三步默认选中「**使用已记忆的费率**」。
- 第一次运行时记忆是空的，程序会弹窗让你填；**只会问本账期实际用得到的那几周**。
- 弹窗里带浅黄底色的数字，是程序**从这份账单反推出来的参考值**，核对 FedEx 官网后点「确定并记忆」即可。
- 之后处理别的客户、别的月份，只要费率周已经记过就不再问；只有遇到没记过的新周才会弹窗补填。
- 「管理已记忆费率...」可以查看、增删、清空，也能导出成 CSV 备份。
- 记忆文件默认存在 exe 同目录 `fuel_rate_memory.json`；若该目录不可写（例如装在 Program Files），
  自动改存到 `C:\Users\你的用户名\.billing_tool\`。换电脑时把这个文件拷过去即可。

## 四、使用步骤

1. 选主文件 → 程序**自动识别客户编码**（先看文件名，再看【汇总】里的客户编号）。
2. 需要的话再添加补充文件（可多选，也可直接把文件拖进窗口）。
3. 填账单月份；燃油费率一般保持「使用已记忆的费率」即可。
4. 点「一键生成结果」。程序先弹**运行前检查**，确认后才开始算。
   出现严重异常（列错位、关键字段缺失、费率未覆盖、1970 年日期、金额列出现文本）会直接阻断。

## 五、输出文件

在原有业务 sheet 之外固定生成：**核对汇总 / 逐单核对 / 漏单明细 / 重复订单 / 跨月订单 /
补充文件覆盖记录 / 费率异常 / 费用字段异常 / 无法解释费用 / 手工调整 / 数据质量报告 / 燃油费率表**。

「核对汇总」底部有一张 **账单原值 vs 明细重算值对账表** —— 这是发现漏单最快的地方。
用五份七月账单实测，四家都有账单金额大于明细合计的情况（详见交付说明）。

## 六、计算规则

**账期归属**由【尾程物流】决定（不是【订单类型】）：

| 尾程物流 | 账期字段 |
|---|---|
| 卡派自提 | 完成时间 |
| 平台快递 | 创建时间 |
| 自有快递 | 创建时间 |

**符号约定**：账单里处理费/物流费/费用总计都是**负数**，附加费明细是**正数**。

\[
\text{燃油基数}=\sum(\text{住宅地址附加费}+\text{偏远附加费}+\text{基础运费}+\text{操作附加费}+\text{操作附加费-尺寸}+\text{超尺寸附加费})
\]

\[
\text{实际燃油费}=\operatorname{ROUND}(\text{燃油基数}\times\text{费率},\ 2)
\]

\[
\text{物流费用}=-\operatorname{ROUND}(\text{燃油基数}+\text{实际燃油费}+\text{PlatformFee},\ 2)
\]

\[
\text{费用总计}=\operatorname{ROUND}\Big(\sum\text{处理费类}+\text{物流费用},\ 2\Big)
\]

**取整**：全程 `Decimal`，逐单 `ROUND_HALF_UP` 到 2 位后再汇总。不用 `float`，不用 Python 内置 `round()`（那是银行家舍入，12.5×0.25 会算成 3.12 而不是 3.13）。

**剔除规则**：只有账期外、已确认测试单、明确取消/作废、客户确认不收费四种才删。
**订单处理费为 0 或为空不再删除**，只记入「费用字段异常」。
测试单关键词默认为空（防误删），需要时在 `customer_config.py` 的 `drop_rules.test_order_keywords` 里填。

## 七、【汇总】sheet 的写法

平台的【汇总】是固定模板（第 7 行账单初账户余额、第 8 行本期总支出、9~16 行八项费用、
19 行期末余额、20 行以后是物流账户第二段）。本版**按 A 列标签文字定位行**写入，
并重算「减 本期账单总支出」和「账期末账号余额」，其余行一律不动。
（旧版是"从第 7 行起顺序覆盖"，会把账单初账户余额等行冲掉。）

## 八、改客户规则

打开 `customer_config.py` → `CUSTOMER_OVERRIDES`，只写与默认不同的部分：

```python
"GUXE": {
    "fuel": {"mode": "none"},          # 该客户不计燃油
    "total_fields": ["订单处理费", "自有运单计费", "复合订单处理费", "物流费用"],
    "fuel_base_fields": [],
},
```

字段名写的是**表头文字**。默认配置里放的是五个客户的**并集**，表里没有的列自动按 0 处理，
所以多数情况下加新客户不用改这里。改完务必跑一次 `python test_regression.py`。

## 九、常见问题

- **「字段结构校验未通过」** → 补充文件比主文件多了字段（MPAV 那次错位就是这么来的）。
  确认新字段合理后，在该客户配置里把 `merge.allow_extra_fields` 改成 `True`。
- **「燃油费率区间存在空档 / 未覆盖」** → 在「管理已记忆费率」里补齐，或导入 CSV。
- **「账期日期异常」** → 源文件里有 1970 年或无法识别的时间，需先在源文件修正。
  注意：只有【卡派自提】按完成时间归属，平台/自有快递的 1970 完成时间不影响计算。
- **「金额列出现文本」** → 金额单元格混进了文字，改成纯数字或留空。
- **重算结果和平台账单对不上** → 打开「无法解释费用」逐单看差额来源，
  多数是费率周边界日（见交付说明中的"周一 vs 周二"问题）和跨月订单剔除造成的。
